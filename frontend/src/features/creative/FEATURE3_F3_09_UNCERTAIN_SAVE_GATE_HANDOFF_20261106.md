# F3-09 — Uncertain private draft save is a stateful recovery gate (2026-11-06)

- Fixed a real client behavior gap: after a v2 `saveDesign` POST timeout, 409 or untrusted response the browser previously showed "Do not retry blindly" but did not actually prevent another POST. It could create a duplicate new document when the first POST had already committed.
- `feature3-draft-write-guard.mjs` now enforces synchronous one-flight writes. A failed request **after the POST may have been attempted** latches an uncertain state and prevents further saves even across rerenders/double-clicks. Local validation failures before POST do not latch an unknown remote write.
- To recover, the same authenticated tenant/day/API must fetch fresh private history successfully. This does **not** silently clear the latch. The user must deliberately reopen a displayed editable draft or choose "Start a separate new draft after checking history" (warns of possible duplicate). A failed/stale GET, foreign shop/day, replaced signed API or late old async callback cannot unlock the prior pending write.
- The feature stays default disabled by its existing server/host flags, never replays POST, performs no GPU/paid inference, hosted SQL or migration, PROD mutation or WineShopPOS changes. Server JWT/RLS, CAS, and media rights remain authoritative. Tests use isolated mock providers and a two-shop synthetic scope; they do not certify hosted acceptance.
