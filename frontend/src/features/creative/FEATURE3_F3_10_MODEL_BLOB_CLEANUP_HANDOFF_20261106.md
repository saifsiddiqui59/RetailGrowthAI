# F3-10 — Fail-closed private model Blob URL cleanup and same-tick load lease (2026-11-06)

- Original bug: Feature3PosterHost revoked old browser Blob URLs before hiding decoded model pixels and without retaining successful/failed per-URL ownership. A browser revoke exception could abort the user-initiated load while old private pixels remained visible and the host retained an inaccurate cleanup array. React busy state was not synchronous protection against duplicate load clicks.
- Added Feature3 private model URL ledger: track only newly created blob: references, revoke each owned handle once, delete successful revocations, retain failed handles to retry and throw an opaque cleanup-pending error. On refresh the component now hides old preview data before revoking; if pending cleanup persists, it refuses further authorized model reads until recovery, while preserving existing no-GPU/approved-model gates.
- Active-read token synchronously prevents double same-tick model GETs. Scope/API unmount invalidates old attempts; stale local Blob URLs are cleaned by exact invocation, with failed handles kept for later retry. Existing image SHA/rights validation and current session/shop guards remain unchanged.
- Synthetic tests cover two private local handles with one failed/successful retry, forged remote URLs, duplicate/disjoint ownership, cleanup order, same-tick gate and source compilation. This is source-only F3-10/F3-13 hardening; not hosted revocation/production acceptance, not a completed original F3-10 package. No paid GPU/provider, hosted SQL, PROD, login bypass or WineShopPOS mutations.
