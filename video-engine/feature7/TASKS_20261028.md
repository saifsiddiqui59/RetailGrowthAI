## 2026-10-28 — CPU-only approved edit dispatch crash recovery (Feature7-owned)

**Independent local source code completed:** `review_dispatch_journal.py` now offers a transactional SQLite/WAL test-only outbox, with a stable `idempotency_key` tied to one persisted local human approval; source SHA/draft/candidate/reviewer/campaign/tenant checks happen in the same SQLite `BEGIN IMMEDIATE` transaction that inserts the dispatch. No client-supplied `human_confirmed` boolean alone can enqueue a job. Replays of a review/approval ID are rejected.

Lease/retry behavior: a job is **READY → LEASED → SUCCEEDED**, or **READY → LEASED → READY** on recoverable failure, or DEAD on exhausted attempts; active revocation fences workers. Short, bounded leases carry unpredictable per-attempt fencing tokens, a monotonically increasing attempt, and the same stable downstream idempotency key. A dead worker's expired lease can be reclaimed; a stale/expired worker cannot acknowledge or heartbeat after reclaim. Crashed *final* attempts become DEAD instead of stranded LEASED. A read-only same-tenant/same-media `reconcile_by_idempotency` resolves an uncertain completion without blindly resubmitting. Test-only `review_dispatch_journal.py` uses a SQLite local `LocalReviewJournal` table in the SAME database for atomic verified human approval; **it is not a replacement for coordinator-owned Supabase/Postgres RLS/outbox**.
