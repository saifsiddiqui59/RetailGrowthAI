# Feature #7 reviewer and private-video authorization — source handoff

## What's implemented in this development continuation

1. `review_actions.mjs` — pure trim adjustment and reviewer-decision state. It accepts only the original verified `NEEDS_REVIEW` proposal, immutable source scene mapping, media byte-verification evidence, bounded source duration and current reviewer view. OWNER/EDITOR can request approval/rejection; VIEWER is strictly read-only. A reviewer adjustment cannot exceed the actual source length or mute the original speech audio. All outputs are `approved:false` and `renderable:false`; they are **requests** for the server.
2. `reviewer_panel.mjs` and `reviewer_panel.css` — isolated, accessible, mobile-sized human review component for Feature #4 to mount *inside its existing authenticated editor*. It previews only an independently trusted private `blob:` URL provided by the host, shows source-relative captions and visual QA, seeks to the chosen trim, and sends a review-request packet through injected `onReviewRequest`. No arbitrary media URL is taken from AI or browser-provided grants, no standalone editor/render/publish endpoint, no auto approval. The host owns blob URL lifecycle and must revoke it after use. This panel is *not yet mounted* on the live site.
3. `media_rights_evidence.mjs` — service-only HMAC (minimum 32-byte server secret), 5-minute maximum TTL, exact tenant / source asset / job / private MP4 relative path / verified SHA256 / registry rights revision. A signed token is not proof of ownership, actual JWT membership or a storage download grant.
4. `authoritative_private_review.mjs` — fail-closed worker entry point requiring a **trusted** `getCurrentApprovedVideo({shop_id,asset_id})` internal callback (must query the live authenticated RLS-backed media registry), same active retailer-upload rights and exact revision, signed rights evidence, original MP4 byte hash/ffprobe, signed ASR evidence, then existing Feature7 speech/caption/gap/B-roll proposals. Browser input never supplies the authoritative grant or media duration. This code is not an Azure Function endpoint; the coordinator must provide the JWT/RLS/DB adapter and stage secure files.
5. Tests: `tests/media/test_feature7_reviewer.py` exercises the reviewer decision and functional DOM control callbacks (including VIEWER/unchecked denial, no self-approval); `test_feature7_rights.py` exercises actual local H264/AAC bytes, current-registry **fixture**, expiry/revoked/foreign/media tamper/forged HMAC and ASR binding. Tests use fabricated trusted contexts and do **not** prove hosted JWT/RLS.

## Integration requirements for the existing Feature #4 editor

- Feature4 UI host should import `mountFeature7ReviewPanel`, `reviewer_panel.css`, and pass the authoritative original `draft`, Feature7 `proposal`, verified read-only `media_evidence`, current server-validated `reviewer_view`, and short-lived private-video **object URLs created by the host**.
- The panel's `onReviewRequest(packet)` is *not* the persistence authority. The host must POST under current authenticated user JWT to a coordinator-approved endpoint, redo RLS current membership/OWNER-EDITOR/rights, compare `expected_revision` atomically, lock immutable original draft hash, verify current video byte/source hashes and valid signed ASR/media rights, persist human confirmation and a one-time review ID before trusting `review_fence.mjs` and the existing F4 `feature4_edit_execution.py`.
- The backend must compute **Feature4 canonical Python `draft_fingerprint`** for approvals, not assume the JavaScript draft hash hint is the same canonical digest for all Unicode/float inputs.
- Reviewer edits are one contiguous source trim per scene only. All B-roll, timed subtitle overlays, internal jump cuts and audio synthesis are *advisory* until Feature4 adds renderer support. Original audio must remain intact for approved trims.
- Do not expose HMAC secrets, trusted rights loader, local staging root, filesystem paths or service-role keys in browser code. Never store external CC0 demo footage as a tenant-owned production upload. Real customer uploads require an additive coordinator-owned video registration migration/API with scoped quotas and private signed playback.
