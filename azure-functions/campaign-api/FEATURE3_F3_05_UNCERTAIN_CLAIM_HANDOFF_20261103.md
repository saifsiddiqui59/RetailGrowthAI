# Feature3 F3-05/F3-13 — unknown outbox SQL claim before Azure Queue send (source-only)

- **Task IDs:** F3-05 GPU outbox / queue dispatch, F3-13 ambiguous ACK and tenant failure regressions. This builds on already integrated pre-publish batch validation; it does not reimplement closed PR #699.
- **Risk:** A trusted service-only `claim_dispatch` RPC can commit its short Postgres lease and then throw from a network timeout, SQL error or injected adapter. Propagating the raw exception can leak backend diagnostics; silently re-claiming or sending would risk an unknown paid job delivery.
- **Fix:** Preserve the existing pre-validation and exact-schema envelope. The dispatch boundary now catches ordinary claim-time exceptions, emits a bounded opaque `StorageUnavailable("...claim uncertain; reconcile before retry")`, suppresses the private exception context, performs **zero** Azure queue sends/SQL confirmations, and does **not** automatically retry. No new queue, GPU, inference or billing action is introduced.
- **Tests:** `tests/api/test_feature3_gpu_queue_publisher.py` adds three deterministic SQL-claim failure types containing a synthetic service-key diagnostic. Each asserts opaque operator-visible failure and zero queue/ACK actions. Existing success, invalid batch, mixed ACK and offline one-shot tests remain.
- **Acceptance:** New final-head four-job GitHub Part 1 CI, independent queue/financial security review, current-main compatibility, approved merge and **fresh postmerge main 4/4** for source acceptance. Real Azure queue delivery/ACK, one-shot GPU worker and unknown outcome reconciliation require owner authorization and runtime evidence; F3-05/F3-13 remain source partial, **0/33 fully hosted complete**.
- **Safety:** GPU OFF, paid inference OFF, no live SQL/Azure/PROD mutation, no unlicensed media or WineShopPOS changes.
