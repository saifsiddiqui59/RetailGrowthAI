# PR integration control — 2026-11-15

## Purpose and authority
The owner requested **existing PRs first**, avoidance of duplicate manual/scheduled work, faster evidence-backed integration, and a concise checkpoint instead of repeated large historic-document audits. This runbook supersedes older automated feature-main-merge guidance *for the current ChatGPT schedules*; it does not change repository branch protection or allow bypassing review, licensing, tenant isolation or four-job CI. The manual integration chat alone is assigned final `main` merge operations for now. Feature schedules code only in their existing owned PRs and may perform separately reviewed child→parent integration; Integration Sprint automation prepares reviewed PRs/duplicate evidence but does not race the manual chat merging to `main`.

## Live queue (separate from code and main)
- Live file: [`coordination/pr_work_queue.json`](https://github.com/saifsiddiqui59/RetailGrowthAI/blob/coordination/pr-execution-ledger/coordination/pr_work_queue.json) on branch **`coordination/pr-execution-ledger`**, not on `main`. Seeded from 68 actual open PRs on 2026-11-15; always refresh from GitHub before trusting counts/SHAs.
- Queue state is **not** `coordination/feature_tasks.json`, `coordination/task_progress.json`, or a claim that a task is DONE. It is a per-PR operational claim/checkpoint inventory; feature registry retains 159 original IDs.
- To claim, first read latest PR state, base and exact head, inspect current queue entry and CAS-update its file through GitHub Contents `sha` on the **ledger branch**. Use `python scripts/coordination/pr_work_queue.py refresh` then `claim --pr N --owner schedule-f2 --head FULL_SHA --next-action '...'` when a permitted GITHUB_TOKEN is available. Without the CLI use the GitHub connector's fetch_file/update_file with exact original blob SHA and branch; if unavailable, do **read-only triage** rather than pretend a lock exists.
- Lease duration 90 min (permitted 10–180), exclusive per PR; an expired lease can be reclaimed after a fresh exact-head PR check, even when its prior head changed. Different owners must not write a PR until its lease expires or is released. CAS conflict (409/412/422) or changed PR head: stop, refetch both GitHub PR and queue, recheck changes; never force. On next hourly execution renew own claim if necessary. A lease is a collaboration aid, **not** GitHub authorization or substitute for independent reviews. Manual chats must also consult/claim the queue to fully prevent collisions. Do not try to acquire a lease while another chat is actively working on that PR.
- `refresh` retains claims, flags moved HEAD, removes no-longer-open PRs from the *live* inventory (GitHub retains full history). `release --outcome ready-for-review|blocked|needs-triage` cannot mark DONE.

## One queue, one main integration owner
1. **Every run:** bounded read of current GitHub PR HEAD/base, queue claim, recent branch changes, and only relevant sections of AGENTS.md, PROJECT_STATE, NEXT_TASK, DECISIONS and WORK_LOG; work the same original task/PR unless already integrated. Never reload multi-hundred-KB docs without reason.
2. **Coding schedules:** F2/F3/F4/F7 own disjoint feature paths; no new PR if an existing PR can safely hold the work. If stale parent is hundreds of commits diverged, extract *distinct* source/test behavior into minimal main-based candidate PRs, retaining attribution to the original PR and avoiding older shared code overwrites. Before new PR, verify no current equivalent already merged and checkpoint this exception.
3. **Integration Sprint automation:** claim as `schedule-integration`, then triage 1–3 unclaimed PRs per run, source-diff comparison, required independent review, exact-head 4/4 CI checks, identify merge conflicts and superseded source; pass only reviewed ready IDs to the manual merge chat. A provenance-preserving unmerged duplicate closure is allowed only with source/test equivalence, current head check, explanatory comment and no active manual claim; otherwise never close to improve counts.
4. **Manual integration chat (single `main` writer):** before each merge verify latest main/PR SHA/changed paths, independent reviews, branch protection, exact-head four CI jobs; merge with expected-head SHA. Verify *fresh main* four-job CI on resulting merge SHA before task DONE; no overlapping merges. Avoid modifying scheduler-owned feature sources unless specifically handed off. Sensitive paths require real independent affected-lead or security review.
5. **Bottleneck rules:** PRs blocked by reviews/CI are explicitly handed off and agents continue a different **unclaimed** task. No idle CI polling, no 10-PR connector exhaustion, no micro-PRs for docs-only checkpoints. Run targeted tests before final full CI; no infinite retry.

## Progress metrics
Record per run: run ID, PR number and head before/after, real code commits, tests and their outcome, exact-head 4/4 status, PRs merged into **main** vs feature parent, duplicates closed with evidence, open PR count at run start/end, and blockers by reason. A run marked 'completed' is not task DONE. The source-only snapshot and ledger branch do not certify hosted tests, approvals, positive tenant/RLS or deployments.

## Limitations
A queued PR claim is only as effective as the workflows that use it. The scheduled task runtime may not have an authenticated CLI environment; the GitHub connector can perform branch/Contents CAS instead when available. A future approved executor can make this enforcement automatic; the current GitHub Actions advisory 10-slot scheduler does **not** run ten coding agents.
