# Feature3 — GPU-off virtual try-on candidate intake and garment QA

2026-10-28. This continues the existing approved model/garment source contract in `fashion_reference_v1.py` and existing human six-check `garment_review_v2.py`, without reimplementing or running a virtual try-on provider.

`poster-engine/feature3_vton_candidate_review_v1.py` accepts only exact model/garment source identity, approved original reference manifest, an externally supplied trusted immutable private-job/lease/rights verifier, a real decoded bounded PNG byte stream and matching SHA. It returns **CANDIDATE_UNREVIEWED** with six explicit human review expectations for color, pattern, neckline, sleeves, length and embroidery, never a marketing license, published output, auto-approved model, registered media or paid authorization.

`tests/media/test_feature3_vton_candidate_review.py` uses existing self-created Pillow kurti and model test images, a spoof-free original data boundary and mocked private-worker verification for positive and negative foreign-shop, changed source fingerprint/model ID, altered candidate hash, expired claim and missing source details. No actual licensed fashion photo or genuine inference was used. The constructed output is synthetic and a valid PNG is **not proof** of an authentic garment being worn.

Existing Feature3 human review and model approval remain separate from this candidate; the provider cannot authenticate itself by setting `inference_executed` or `approved=true` in a public payload. A secure integration must verify real provider receipt, private output CAS (#565), current source rights, usage/cost lease and independent human visual comparison. The existing FASHN parser dependency commercial licensing remains unresolved, and no GPU/model API must be called without separate owner release approval. Source-only PR requires exact-head 4/4, coordinator merge and independent main CI. No hosted DEV migration, paid services, PROD or WineShopPOS modifications.
