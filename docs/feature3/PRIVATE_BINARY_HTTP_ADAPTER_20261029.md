# Feature3 no-URL generated PNG HTTP response adapter — source-only 2026-10-29

- Existing `Feature3RevocablePNGReader` verifies signed Supabase user JWT, current RLS membership, same-shop successful job+private output, active independently approved rights and real PNG bytes; it rechecks current membership, output and rights after reading bytes. This new **`feature3_private_binary_http.py` pure adapter** consumes the existing reader, never a caller-provided object path or a signed Storage link.
- GET requires one signed Bearer token; all non-GET methods are 405 without invoking reader. Missing/malformed or service-role token is 401; revoked/missing/foreign output 404; uncertain backend state or mismatched receipts 503. No data/URL/path is returned on failure. Successful 200 requires exact receipt keys, same shop/job, canonical asset, private=True, approved_model=False, publish_approved=False, signed_url_issued=False, actual SHA-256 of bounded PNG bytes. Headers include image/png, fixed safe filename, Content-Length, Cache-Control: no-store/private, Pragma: no-cache, X-Content-Type-Options: nosniff, Content-Security-Policy default none and Vary: Authorization.
- `tests/api/test_feature3_private_binary_http.py` generates real Pillow PNG, uses an injected mock reader, and denies wrong tenant, changed bytes/digest, forged publish/approval, extra signed URL, wrong method and rights service failure. No actual network or paid inference.
- **No Azure Functions public route was added.** The existing signed 60s URL route still exists; old links cannot be revoked retroactively. Coordinator must approve a versioned binary route and a real independently reviewable output rights callback backed by live tenant+source evidence. Frontend still needs exact SHA/tenant Blob preview and on-switch revocation. Live owner/editor/viewer/revoked and Azure #249 checks remain pending. No GPU, PROD, migration or WineShopPOS changes.
