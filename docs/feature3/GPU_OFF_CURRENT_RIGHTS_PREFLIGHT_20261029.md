# Feature #3 GPU-off trusted job/source plan preflight — 2026-10-29

## Delivered source
- `azure-functions/campaign-api/feature3_gpu_job_plan.py` adds `Feature3GPUJobPlanPreflight`, **read-only**. A queue message carries only shop/job UUIDs; preflight reconstructs authoritative existing `feature3_gpu_jobs` status/attempt, current active OWNER/EDITOR author, live TRIAL/ACTIVE subscription+period, exact versioned `feature3_poster_designs` SHA/revision/layer sources, currently registered same-shop private `media_assets` and, when a registered asset is a model, its approved/current `feature3_models` metadata. Duplicate/foreign/invalid records, unsafe object keys and reviewer grants deny.
- Per-source `source_proof(shop_id, actual registered media row)` is mandatory trusted private backend evidence (not user-supplied, demo manifest or a mere `license_name`). Each proof must include exact shop+asset, SHA256, rights_revision, byte SHA verified, independent commercial license verified, current customer approval and rights not revoked. Model-source proof must match independently approved catalog SHA. Verify all immutable proof fields twice, with the second check **after rereading all authoritative SQL rows**, detecting revocation with or without SQL metadata drift.
- `AdminStore.request` now exposes only the three existing service-only SQL planning tables (`feature3_poster_designs`, `feature3_models`, `shop_subscriptions`) for GET and disallows generic writes to these plus existing `feature3_gpu_jobs` and `shop_ai_spend_reservations`. Claim/finish/commit/dispatch still require current one-shot approved RPCs. No schema added.
- `tests/api/test_feature3_gpu_job_plan.py` uses synthetic DB/rights fakes to test allowed plan and denial for foreign, revoked, expired, malformed licence, wrong model, changed job, stale source after first proof, invalid design and non-RPC generic writes.

## Strict limit
The returned plan is a private **readiness inspection**, always `provider_call_permitted=false`, `claim_performed=false`, `gpu_started=false` and `paid_retry_authorized=false`. No Azure Queue trigger, worker deployment, credential handling, paid GPU start, inference, financial settlement or actual data read occurs here. Production **must implement** a genuine independent source-provenance/rights byte reader, review evidence source, and call it only behind approved backend deployment; never use the test fake as an authorization service. Preflight is not a durable lease claim and must be repeated after an actual one-shot SQL claim (which itself remains disabled until proper spend authorization).
