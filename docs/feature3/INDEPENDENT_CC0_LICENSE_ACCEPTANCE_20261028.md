# Feature3: independent real licensed-image acceptance (GPU OFF)

2026-10-28. This is a **real single public source photo** and license metadata verification test, separate from user-owned private signed tenant acceptance and actual virtual try-on. It **never** starts a model or a paid API.

**Official candidate**: Wikimedia Commons [Bengal mundari saree photos.png](https://commons.wikimedia.org/wiki/File:Bengal_mundari_saree_photos.png), uploaded by Mundasing7215, original 1055×899 PNG, 1,437,034 bytes, published CC0 1.0, official SHA1 `0a1208be9af509df01bd043cbade7e4d7bb3252e`. The source is an external copyright-license declaration, NOT a retailer-owned SKU or consent to change a recognizable person's clothes. Reconfirm current page and file before any reuse.

**Implementation**: `poster-engine/feature3_commons_license_v1.py` validates actual retrieved private bytes with Pillow, bound size/pixels, and compares both byte length and SHA1 against the authoritative Wikimedia Commons `imageinfo` response from a fixed HTTPS endpoint. It verifies CC0 licence and exact official Creative Commons license URL; prevents third-party redirects, forged source domains, malformed metadata and unauthorized foreign private media. It returns a strictly limited garment-source proof with `license_verified_on_source=true` while `model_likeness_release_verified=false`, `retailer_product_ownership_verified=false`, `virtual_tryon_approved=false` and `gpu_authorized=false`. Tenant authorization is supplied only by existing signed JWT/RLS backend, never established by Wikimedia.

**One-time real source CI**: `.github/workflows/feature3-commons-real-photo-once.yml` attempts to fetch the exact single original via Commons Special:FilePath, pins the published SHA1/size, queries live official Commons metadata and validates actual pixels, prints only a nonsensitive hash/rights receipt, and deletes the file. Network/source availability is not guaranteed; do not call it PASS until the dedicated Actions run genuinely succeeds. No bulk photo scraping, dataset building, third-party person likeness, sensitive user data, Azure, hosted DB or paid inference.

**Limitations**: This does NOT certify source identity as an actual customer's garment, registered private tenant media or an identifiable person's model consent. Existing #553 private JWT/RLS reader + independent original shop source registry, explicit model release and signed human/curator approval are still mandatory. For *actual* VTON visual quality, run current officially documented FASHN `tryon-v1.6` or approved equivalent only with a funded API account, approved real garment/model images (including releases) and explicit bounded cost approval, capture final real output bytes, and have a person compare six traits (color, pattern, neckline, sleeves, length, embroidery) using existing #571 and `garment_review_v2`. No provider invocation or genuine VTON output was performed by this PR.

Release gates unchanged: current Supabase DEV had 24 applied versions as of read-only check; host migration/owner and curator sign-in and #249 reliability still pending. GPU OFF, no WineShopPOS touches.
