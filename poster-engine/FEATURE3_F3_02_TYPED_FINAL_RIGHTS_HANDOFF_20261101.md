# Feature #3 F3-02 / F3-13 private worker final-read grant revision guard

## Source-only security issue
The existing `poster-engine/feature3_worker_input_handoff.py::_final_read` checks a current private media grant before reading original garment/model/try-on bytes, but compared `rights_revision` using Python's ordinary equality. A transient mocked or malformed authoritative callback with `rights_revision=True` or `1.0` could incorrectly equal an immutable revision `1`, so the final-byte read boundary would fail open on malformed rights metadata.

## Change
- Require `type(grant.get("rights_revision")) is int` before checking the exact approved revision. No other paths/authorization contracts are changed.
- Add a deterministic **full `resolve_private_worker_inputs` path** test with synthetic in-memory bytes: establish revision 1, inject malformed `True` or `1.0` only on the final garment-grant callback, and prove the packet is denied at that check. A later healthy grant must not excuse the transient invalid current grant.
- Original task IDs: **F3-02** private worker materialization and **F3-13** cross-tenant/rights negative regressions. Existing source components were previously integrated through Waves A/B; this is a distinct previously untested *intermediate* input-revision type gate.

## 2026-11-02 — Complete final-read license snapshot fence (F3-02/F3-13)
- A final worker `_approved_asset` read could return a transiently substituted **license name or attribution** while preserving shop, asset ID, source kind, immutable SHA, dimensions and integer rights revision. The previous `_final_read` compared only those selected fields. If the next rights refresh reverted to the original metadata, a worker packet could be returned even though the final byte read observed a different license snapshot.
- `_final_read` now compares the **entire normalized approved source reference** to the immutable manifest reference. This includes license/attribution and all current and future approval/identity fields, rather than a partial whitelist. It does not grant rights or bypass the separate current lease, full manifest, or final rights checks.
- Added `test_transient_private_license_snapshot_change_denied_at_final_read` to inject attribution-only and license-name/URL-only substitutions **only on the second garment source read**, then restore the valid original. The packet must be rejected at the final read, before the later clean snapshot could hide the transient mismatch. Tests use only offline synthetic image bytes and trusted callback fakes.

## 2026-11-02 — standalone Feature5 first-frame post-byte lease and rights fence
- The direct `resolve_first_frame` consumer previously checked its durable worker claim **only before** the final private image read. A lease revoked while Storage returned the image could still yield bytes to the Feature5 worker; the surrounding `resolve_private_worker_inputs` lease rechecks do not protect callers of this standalone function.

## 2026-11-02 — decode-complete private JPEG input (F3-02/F3-13)
- `fashion_reference_v1._read_image` previously accepted a JPEG after Pillow `Image.verify()` without decoding pixel data. A truncated JPEG missing its end-of-image marker can pass `verify()` and match a registered SHA of the *same truncated bytes*, then reach the private worker manifest despite being undecodable.
- The source verifier now additionally calls `load()` on a fresh Pillow image handle after `verify()`, before returning the approved source reference. This preserves the existing 25 MB/24 MP and format/dimension limits while rejecting incomplete JPEG scan data. It does not perform any GPU work.
- Added a deterministic synthetic 320x320 JPEG control and two truncated-byte negative cases in `tests/media/test_feature3_fashion_reference.py`, each with its own matching registered SHA, to demonstrate integrity hashing is not sufficient without full decode. No customer images or hosted media used.
- Original IDs **F3-02/F3-13**, existing **PR #862**. Targeted test: `python -m unittest discover -s tests/media -p 'test_feature3_fashion_reference.py'`; mandatory exact-head 4/4 PR CI and independent Feature5/private-media security reviews still gate merge. No hosted acceptance; 0/33 hosted DONE.

## 2026-11-03 — F3-02/F3-13 immutable model-library namespace before private reads

- Continued existing PR #862, original task IDs **F3-02** (private worker materialization) and **F3-13** (tenant/rights negative tests), without a new PR or shared interface change.
- The trusted in-process FashionReference reader previously accepted a same-shop model-library PNG path based only on a loose minimum segment count, PNG MIME and a matching post-read digest. A forged model-original path could reach a privileged `read_private_bytes` call before canonical namespace validation.
- For model originals only, `_approved_asset` now requires **exactly** `shop/model-library/{canonical-model-uuid}/{registered-sha256}.png` or `shop/model-library/platform/{canonical-model-uuid}/{registered-sha256}.png`, with an exact lower-case 64-hex SHA filename matching authoritative `media_assets.image_sha256`, before any private bytes are read. Existing garment upload and try-on paths retain their separate validated namespace contracts; this is a strict source check, never a rights approval.
- Added offline actual Pillow/image-authorizer tests for eight malformed or SHA-mismatched model-library keys, asserting **zero private model-image byte reads**, plus a valid platform-library UUIDv5/SHA control. Tests use synthetic images only and cannot prove legal/commercial approval.
