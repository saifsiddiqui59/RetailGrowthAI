# #249 Y1 authenticated campaign GET shadow — source integration checkpoint

**Purpose:** Take the first original RetailGrowthAI authenticated, tenant-fenced API route toward the *already-hosted* alternative Y1 Function App without enabling any background workers or switching retailer traffic.

## Source / package
- `ops/p0249-y1-readonly-campaign/campaign_read/`: exactly one explicit Python v1 `GET /api/campaigns/{campaign_id}` handler, not a fork of tenant access logic.
- ZIP assembly copies **verbatim** the original `http_api.py`, `security.py`, `tenant_store.py`, `draft_api.py`, `request_diagnostics.py` from `azure-functions/campaign-api/`, and original `ai_agents.schemas` from `ai-agents/src/ai_agents/`. The same Supabase JWKS + authenticated role, current active member + RLS read path is invoked, with `planning_queue=None` and `render_api=None`. No service role, queue/timer triggers, GPU, mail, AI or render worker is packaged. No SQL writes are available through the bound GET method.
- Mandatory activation gate `RGAI_P0249_READONLY_SHADOW=true` together with actual `RETAIL_SUPABASE_URL` and *public* `RETAIL_SUPABASE_PUBLISHABLE_KEY` prevents accidental real JWT/database activity. It is **intentionally NOT enabled** or populated by this deployment. Requests with no/malformed authorization always return handler-marked HTTP401 without reading config. A Bearer-shaped value while disabled receives a fixed handler-marked HTTP503 `SERVICE_NOT_CONFIGURED`.
- No real signed DEV two-shop JWTs, Supabase settings, or customer data are copied. Credential configuration requires separately reviewed deployment, coupled with signed positive/negative 2-shop test evidence before any routing.
